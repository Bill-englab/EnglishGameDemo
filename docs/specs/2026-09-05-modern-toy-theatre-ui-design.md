# 现代玩具剧场 UI 统一改造

> 日期：2026-09-05
>
> 状态：视觉方向已获用户批准；等待本文件书面复核
>
> 覆盖：地图、应用外壳、Stage/课程目录、课程详情与手机适配
>
> 不覆盖：课程台词、完成规则、媒体路径、AI 教学、Stage 2/3 内容生产

## 1. 目标

把目前“功能齐全但有手工拼装感”的界面重做成一套统一、精致、现代的家庭产品。视觉采用用户选定的 **B · 现代玩具剧场**：地图是有真实材质与空间层次的微缩世界，界面文字与操作保持平整、克制、易读。

产品本质不变：网站仍是孩子表演录像的奖杯陈列柜；只有当前用户的 `performance` 视频能点亮课程。地图的主要奖励是可回看的视频封面，不新增星级、积分、连续打卡或能力评分。

## 2. 视觉基准

四张批准效果图是同一系统的组成部分：

- [桌面地图](../../design/reference/modern-toy-theatre-map.png)
- [课程详情](../../design/reference/modern-toy-theatre-detail.png)
- [Stage 与课程目录](../../design/reference/modern-toy-theatre-drawer.png)
- [手机地图与详情](../../design/reference/modern-toy-theatre-mobile.png)

效果图负责气质、构图、层级、材质与密度，不覆盖真实数据规则。图中的人物、关卡编号和进度只是构图占位；实现必须读取真实 library，按每章 3 课、全 Stage 30 课呈现。手机图中已用完成环代替误生成的星星；项目始终只有二元完成状态。

### 2.1 设计系统

- 地图世界：柔和日光下的黏土、彩绘木、磨砂陶与织物，边缘圆润但不塑料化。
- 内容底色：暖象牙白 `#fffaf2`；主文字深可可 `#402b20`；次级文字 `#73635a`。
- 主强调：深青绿 `#267f7b`；悬停/当前态 `#319791`；孩子台词杏色 `#ffddb0`。
- 边框：`#ded2c3`；高风险/录制只用克制红色 `#db493f`。
- 阴影只用于地图节点、浮动外壳和抽屉；正文靠留白、字号和细分隔线建立层级。
- Fredoka 用于页面和分段标题；Nunito 用于正文和操作。对话桌面约 17–18px，手机不低于 16px；辅助文字不低于 14px。
- 控件至少 44×44px；统一 SVG 图标、10–14px 控件圆角、18–20px 浮层圆角和 4/8/12/16/24/32 间距序列。
- 不照搬效果图里的厚木框、过多浮雕或强阴影。场景可以立体，应用控件保持现代轻量。

## 3. 可分离的视觉层

### 3.1 章节场景资产

十章都替换为同一 3D 微缩材质语言，但保持不同场景身份：

| 章 | 微缩世界主题 |
| --- | --- |
| 1 选择与请求 | 果园、彩色风车、野餐布 |
| 2 拒绝与协商 | 柔和色彩市集、可收拾的小摊 |
| 3 求助与澄清 | 木制积木与手工工作坊 |
| 4 身体与需要 | 舒适家庭角落、饮水与休息线索 |
| 5 日常与转换 | 晨间准备小镇、衣帽与时间线索 |
| 6 寻找与归属 | 玩具公园、收纳与失物线索 |
| 7 加入与合作 | 共同搭建的游乐工地 |
| 8 感受与修复 | 花园、小桥与可修复的共同作品 |
| 9 外出与安全 | 商店、车辆与安全等候点 |
| 10 讲述与计划 | 家庭露营地、路线与明日计划板 |

每章制作两个无 UI、无文字、无人物、无关卡节点的本地资产：桌面 8:5 和手机 9:16。构图预留宽阔的中央/之字形草地通道；真实路径和节点仍由代码绘制，避免把路线烘焙进图片后在不同宽高比错位。命名采用 `app/static/worlds-v2/<world>-desktop.webp` 与 `<world>-mobile.webp`；加载失败回退现有插画。

### 3.2 代码绘制层

SVG 路径改成有轻微厚度的浅色“石板路”：底层柔和阴影、中层暖灰描边、上层象牙白；完成段增加低饱和青绿内线，不使用强金光。节点、视频封面、状态图标、标题和所有控件都是 HTML/SVG，不嵌入背景位图。

三种节点保持现有语义：

- `completed`：清楚的视频封面＋单一青绿勾；没有封面时为完整的材质回退节点。
- `current`：视频封面＋青绿定位针/双圈，只有低频轻呼吸；不默认显示“完成”。
- `locked`：可辨识封面或编号回退＋锁；仍可点击预习，不压暗到看不清。

节点使用课程真实标题作为可访问名称；视觉上的小编号只取该 Stage 的真实顺序，不影响文件路径和排序。

## 4. 应用外壳与进度

地图不使用整条白色标题栏。顶部是三个独立浮动组：菜单与 Stage、真实 `完成数 / 30` 与简洁进度条、用户头像；Electron 窗口按钮在最右侧，Web 不留空位。桌面中央保留可拖动区，交互元素全部 `no-drag`。

“Current lesson” 是轻量浮动按钮：只在存在当前未完成课时显示，点击滚动并聚焦真实 `current` 节点，不自动打开、不播放、不录制、不更改进度。Stage 全完成时改为简短完成提示并隐藏按钮。

加载失败保留已渲染地图并提供重试；没有缩略图时使用节点回退，不让图片失败破坏布局。

## 5. Stage 与课程目录

菜单打开 340px 暖白抽屉；手机占屏幕大部分宽度。抽屉包括：

1. 当前 Stage 摘要与真实完成数。
2. Stage 1 可用；Stage 2/3 显示能力主题和 `Planned`，使用禁用控件，不伪装成可进入内容。
3. 10 章折叠列表，每章显示真实完成数；默认展开当前课所在章。
4. 每课同时表达课程状态与当前选择，不能把“当前”误画成“已完成”。点击课后关闭抽屉并打开真实详情。
5. 账户与资料入口。

打开抽屉后背景不可交互且地图滚动锁定；焦点进入抽屉并限制在其中。Escape、关闭按钮和遮罩都能关闭，之后焦点回菜单按钮。目录和页面各自只有一个滚动容器。

## 6. 课程详情

保留已经验证的结构：56px 单行工具栏；桌面左 340px 媒体栏，右侧完整阅读；小于 900px 使用媒体页签和单列正文。

本轮只做视觉统一和细节收敛：

- `Your Show` 始终优先。空状态使用 `Record your roleplay` / `Start recording`，可用当前章节的低对比场景裁切作为背景，但不能冒充已有录像。
- `Watch & Learn` 保持紧凑的 `No demo yet` / `Add demo`；有视频时使用真实原生播放器。
- A/B/C 的所有台词、角色、两张 Replay、Grown-up Notes 与 VideoGen 原样保留，不为视觉简洁删内容。
- 成人台词为白/象牙底，孩子台词为杏色；减少大卡片嵌套，阅读层级由分段标题、气泡和细线建立。
- demo 上传完成只刷新 demo 面板，不能破坏正在录制或尚未保存的 performance。
- Previous/Next 保持内容底部；手机预留安全区，不覆盖正文。

详情背景是安静的暖白，不让 3D 地图穿过阅读正文。可在最外缘使用非常克制的木材/青绿边缘呼应地图，但不能形成厚重相框。

## 7. 手机与小窗口

- 小于 768px：全屏地图、顶部紧凑控件、足够大的视频节点；详情为媒体页签＋单列完整阅读。
- 768–1023px：紧凑桌面布局；Electron 800×600 仍可使用，不出现横向滚动。
- 1024px 以上：完整地图与舒适详情双栏。
- 背景根据断点切换桌面/手机资产，不简单放大裁切。
- 触摸目标、系统缩放、横屏、长标题和 `safe-area-inset-*` 都必须验收。
- 隐藏的视频暂停；响应式切换不能销毁摄像头、计时器或未保存回放。

## 8. 功能范围

本次实施包含：

- 20 张统一的章节背景资产及失败回退。
- 新外壳、地图视觉、节点视觉、真实进度和“Current lesson”。
- Stage/章节/课程抽屉。
- 详情与手机端的 B 视觉收敛。
- Electron/Web 的窗口控件与响应式适配。

此前已同意但效果图未定义的 **3 秒录制倒计时** 和 **0.75×/1× 手机播放速度** 不混入本次视觉改造；它们保留在原沉浸 UI 规范中，后续作为独立行为任务实现。这样可以避免在大规模视觉迁移中同时改变录制状态机。

登录、管理和个人资料只对齐颜色、字体、按钮与边框 token，不重排信息架构。课程、认证、上传、压缩、缩略图、用户隔离和 Stage 04 媒体路径不变。

## 9. 模块边界与数据流

- `map-model.mjs`：继续拥有 world/颜色/节点视觉纯映射，扩展响应式背景资产描述。
- 新的纯模块：负责 Stage 展示模型、章节完成计数、目录展开状态和 current 跳转目标；不读取 DOM。
- 新的 UI 编排模块：负责 shell/抽屉焦点和滚动锁；`app.js` 只连接 library、详情和录制生命周期，不继续堆入抽屉实现细节。
- `style.css`：提取全局 token 与地图/详情公共组件；需要时拆出 shell/map 样式，但不引入构建器。

数据流始终为 `/api/library` → 纯投影（完成数、Stage/章/课状态、world assets）→ 地图与目录。任何 UI 选择都不能回写课程状态；只有 performance 上传后重新加载 library 才改变完成数。

## 10. 错误处理与安全

- 背景、缩略图或视频失败各自局部降级，不让整个地图/详情消失。
- 目录异步刷新使用详情访问/请求代次守卫，旧响应不能打开错误课程。
- 抽屉关闭、地图导航和详情切换必须释放焦点锁、视频播放和摄像头资源。
- 所有视觉验收使用隔离账号、demo 与 recordings；不通过启动扫描或测试上传触碰家庭录像。
- 资产只存仓库本地，不加载 CDN 或外部账户。

## 11. 验收

### 自动检查

- Python 全套：认证、课程、媒体路由与 HTML 外壳继续通过。
- Node：新增 Stage/目录/current 纯逻辑与背景资产映射测试；保留路径、状态与媒体页签测试。
- HTML 结构测试：菜单/抽屉 ARIA、唯一主滚动区、Electron/Web 控件挂载点。

### 浏览器与 Electron

- 桌面 1440×960、Electron 最小 800×600、手机 390×844、手机横屏。
- 10 章连续滚动、每章 3 节点、路径与节点中心在字体/图片加载及 resize 后对齐。
- 目录焦点、Escape/遮罩/关闭、真实课导航和滚动恢复。
- 完成/current/locked、有无 demo、有无 performance、图片加载失败。
- 详情录制、未保存回放、demo 上传、手机页签、Previous/Next 不因重排回归。
- 真实 Electron preload 的最小化、最大化、关闭和拖动区。

### 视觉验收

实现前从四张批准图提取 token、组件和图标清单。实现后在批准图原生尺寸与真实浏览器截图逐项比较：构图、色值、字号、间距、边框、阴影、节点比例、场景裁切和移动端密度。至少记录五项 fidelity ledger；未达到设计机构交付标准不得宣布完成。

## 12. 明确不做

- 不实现教学引擎、AI 对话、评分、星级或生日自动升级。
- 不创建数据库、前端框架、打包器或云依赖。
- 不生成 Stage 2/3 空课程，不伪造完成数据。
- 不修改 curriculum 台词、角色、Replay 或 `content_revision`。
- 不覆盖、移动、删除现有 demo、recordings、头像、账号或配置。
