# 视频压缩检查记录

> 日期：2026-09-04；检查对象：当前本地代码与检查环境。仅诊断，未修复，也未验证实际部署服务器。

## 已确认的代码行为

`app/app.py` 的 upload 路由先保存原文件，再同步调用 `_compress_video`；demo 还会生成缩略图，之后才返回成功。超过 5 MiB 才尝试压缩。服务端压缩不减少首次上传的流量。

1. 当前检查环境的 PATH 没有 ffmpeg，运行测试的 Python 也没有 imageio-ffmpeg；项目 `app/.venv` 不存在。不能据此推断另一台部署服务器也缺少依赖。
2. `_compress_video` 找不到工具时返回 False，但上传路由忽略该结果，仍返回成功，页面看不出视频未被压缩。
3. 后端只精确识别 `video/webm` 和 `video/mp4`。录制端可能发送 `video/webm;codecs=vp9,opus`，实际会被归为 `.mp4`；文件选择上传还没有发送 mimeType 字段。
4. 压缩函数固定 H.264/AAC 编码，却沿用输入文件后缀作为输出后缀；WebM 输出与该编码配置不匹配。函数也没有检查进程退出码，仅按输出存在且更小决定替换，有误用不完整输出的风险。
5. 两个详情视频都设置 `preload="auto"`；MP4 编码未设置 faststart。它们是加载优化候选，不是已复现的远程慢网根因。

MP4 索引前置有助于尽早开始播放，见 [FFmpeg 格式文档](https://ffmpeg.org/ffmpeg-formats.html)。

## 本次验证与限制

已运行现有测试：Python 87 项、JS 11 项通过；现有测试不等于真实压缩验收。

用 Flask 测试客户端和临时目录提交两次 6 MiB 的合成字节载荷，用户名仅为临时测试 session 的 audit_user：

| 提交 MIME | 保存扩展名 | 返回状态 | 保存大小 |
| --- | --- | --- | --- |
| video/webm | .webm | 200 | 6,291,456 字节 |
| video/webm;codecs=vp9,opus | .mp4 | 200 | 6,291,456 字节 |

该载荷不是有效视频，只验证缺少编码器时上传仍成功以及 MIME 归类错误；不能据此报告压缩率、画质或视频可播放性。临时目录在检查后清理，未访问或改写真实录像。

没有真实视频编码、远程限速环境或部署日志，因此尚未定位用户此前慢加载的唯一原因。后续修复需要有效 MP4/WebM 临时样片、实际编码器、退出码/可解码性/输出格式测试，以及分开测量上传、处理和播放等待。
