# Design Proposal — 英语 Role-play 闯关网站

> 日期：2026-08-01
> 建立在 `.vibe/memos/memo-original-request.md` 的需求讨论之上。本文件记录**已确认的设计决定**。

---

## 1. 一句话

一个**本地**网站，把父子线下 role-play 的录像，排成一条"章 → 关"的闯关地图；每过一关，地图上那个点就变成**孩子自己录像里的一帧**。网站是奖杯陈列柜，不是老师。

## 2. 定位（已确认）

- **不是教学引擎**。真正的英语教学在线下 role-play 里发生。
- 网站只做两件事：① 把进度可视化成游戏般的地图；② 让孩子能反复回看自己的表演。
- 原始诉求里的"句式更高级"是**线下练习**的目标，不由网站量化显示。

## 3. 地图设计（决定 B：主题 = 章，章内分关）

```
Ch.10 planning-predicting   ★ ★ ★ ★
Ch.09 reporting-others      ★ ★ ★ ·     ← 正在这关
Ch.08 recounting-day        ★ ★
···
Ch.01 wants-requests        ★ ★ ★ ★ ★   ← 满章，常回来回味
```

- 全图 = 10 章 × 每章几关（预计 **30~50 关**）。
- 选 B 的理由：4 岁娃需要**频繁的小奖励**；只 10 颗星太少、爬完太快。
- 代价：备课要做的"演示视频 + 文案"不是 10 份，是 30~50 份。

### 关卡状态

| 状态 | 触发 | 显示 |
| --- | --- | --- |
| 锁住 | 上一关还没有 `performance.mp4` | 灰圈/锁，不可点 |
| 已解锁、未完成 | 上一关已完成，本关还没有 `performance.mp4` | 可点开看 demo，未亮 |
| 已完成 | 本关有 `performance.mp4` | **孩子录像的一帧缩略图（他的脸）** + 角标小星 |

## 4. 节点外观（脸封面，已确认）

点亮的关，圆点直接变成**孩子那段表演视频里的一帧**（认得出是他的脸）。星星降级为完成角标。

> 理由：4 岁娃对抽象 ★ 无感，认的是脸。点脸 → 播他自己那段 → 这才是他反复回来点开看的动力。

## 5. 每关的组成

| 文件 | 来源 | 作用 |
| --- | --- | --- |
| `meta.json` | 备课 | 关卡标题、对话文案、场景描述 |
| `demo.mp4` | 备课（AI 生成动画） | "看样板"——演示这段对话怎么演 |
| `performance.mp4` | 父子排练后录制 | "看自己"——孩子的表演；**存在 = 通关** |

教学逻辑：**样板 → 练 → 演 → 录**（I-do / We-do / You-do）。

## 6. 数据结构（两层文件夹：章 → 关）

```
roleplay-dialogues/
  01-wants-requests/          ← 章（主题）
    01-i-want-water/          ← 关（场景）
      meta.json
      demo.mp4
      performance.mp4         ← 有它 = 这关亮
    02-i-want-to-go-out/
      meta.json
      demo.mp4
  02-refusing-bargaining/     ← 下一章
    01-no-thanks/
      meta.json
      demo.mp4
```

### 状态规则（三句讲完）

- **顺序**：先按章序、章内再按关序。
- **解锁**：上一关文件夹存在 `performance.mp4` → 下一关解锁。
- **点亮**：当前关文件夹存在 `performance.mp4` → 显示脸封面 + 角标。

## 7. 运行方式

- **本地运行**，不部署公网。
- **文件系统即数据库**：网站扫 `roleplay-dialogues/` 即知一切，零后端、零上传接口。
- "上传" = 父亲**手动**把 `performance.mp4` 拖进对应关文件夹。

## 8. 两个阶段

1. **备课**：父亲独立完成——搭网站、写每关文案、用 AI 生成 `demo.mp4`。
2. **使用**：父子一起——看 demo、练、录表演、拖文件、脸封面上线。

> **瀑布式提醒**：不要"备完整套课再上"。先贯通**第一关**（一站 + 一关 + 能录能放能点亮），本周试一次，再扩。

## 9. 一次典型的"使用"流程

1. 娃点开当前关（或父亲代点）→ 播 `demo.mp4`，看这段怎么演。
2. 父子照 demo，线下反复 role-play。
3. 练熟，录一段 `performance.mp4`。
4. 父亲把视频拖进这关文件夹。
5. 网站检测到文件 → 这关点亮（脸封面）→ 娃点自己的脸，回看那段。

## 10. 待定的小决定（不阻塞开工）

- **谁点屏幕**：娃自己戳（超大按钮、不认字也能玩） vs 父亲操作、娃只看。
- **点亮仪式**：拖文件进去 → 星当场"啵"地亮给他看（小仪式） vs 下次打开才发现。

## 11. 不做的事（明确排除）

- ❌ 教学引擎 / AI 对话搭档（教学在线下）
- ❌ 上传页 / 后端上传接口（手动放文件）
- ❌ 1/2/3 星分级（一颗星，二元）
- ❌ 公网部署（本地跑）
- ❌ 用星星追踪"句式高级度"（那是线下目标）

## 12. 风险（沿用备忘，父亲自检）

| 风险 | 守则 |
| --- | --- |
| AI 演示视频质量（两角色对话仍偏弱） | 备课前先验证工具，再批量生成 |
| 录像变考核，娃开始躲 | 录像应是游戏高潮，不是小考 |
| 备课节奏跟不上闯关节奏，地图断更 | 接受缓慢生长 / 先备缓冲 |
| 手机→电脑拖文件的摩擦 | 首关贯通时实测要几秒 |
