# 沉浸冒险 UI 与跨端设计规范

> 日期：2026-09-04
>
> 状态：B 方向与导航修订已获用户确认；本文等待实现前书面复核。
>
> 范围：地图、课程详情、课程目录与 Electron/Web 公共界面；不修改教学内容或进度规则。

## 1. 已确认的方向

采用 B「沉浸冒险」：绘本地图铺满可用画面，路径和关卡在其上；工具按需展开，不常驻侧栏。去掉独立标题栏，在左上角提供 Stage、章节和课程目录。

主界面使用 Stage 1 / 2 / 3 与能力主题；年龄保留为家长选课、内容创作的参考，不作为生日升级或入学门槛。

设计依据为本次会话已确认的 B 草案及其无标题栏、弹出目录修订。草案只是布局与交互依据，不包含真实媒体、录制或窗口操作；正式实现必须接回现有功能，不复制草案中的演示按钮。

## 2. 产品规则不变

- 网站是表演录像与成长进度的陈列空间，教学发生在线下。
- 只有对应用户的 performance 视频能使课程完成；进入目录、点击课程、播放 demo 都不改变完成状态。
- completed / unlocked / locked 的判定沿用当前状态机；锁定课仍可浏览、预习，不新增访问禁止规则。
- 不增加能力评分、连续打卡、错误统计、AI 教学或自动年龄评估。
- 不重写课程，不恢复 demo 生产，不移动或覆盖已有视频。
- 保持 Flask、原生 ES Modules、自托管字体、本地文件系统；不引入前端框架、打包器或云依赖。

## 3. Stage：展示名与内容身份分开

| 展示名称 | 沟通重点 | 设计年龄参考 | 稳定内容身份 | 本轮可用性 |
| --- | --- | --- | --- | --- |
| Stage 1 · I can take part | 参与、回应、求助、澄清 | 约 4 岁 | `04` | 展示当前已编写的 30 课 |
| Stage 2 · I can keep it going | 追问、解释、协商、维持对话 | 约 5 岁 | 预留 `05` | Planned，不可进入 |
| Stage 3 · I can explain and adapt | 叙事、说明、根据情境调整表达 | 约 6 岁 | 预留 `06` | Planned，不可进入 |

Stage 不是语言能力评级。家长结合回应能力、兴趣和年龄适宜性选择，不由网站自动判断。不能以孩子的生日改变选择、解锁课程或重置进度。

`Phase A–D` 仍为一个 Stage 内部的教学分段，不增加孩子导航层级。主导航只展示 Stage → Chapter → Lesson。

实施时，展示序号、能力主题、参考年龄与稳定身份分别表达；禁止通过显示文字反推媒体路径。`curriculum/04`、`demo/04`、`recordings/<user>/04`、`prompts/04` 原样保留。

本轮只有一个完整可用 Stage，不声称实现了多阶段运行时切换。Stage 2、3 提供简短规划说明与禁用状态，不生成空课程。未来启用真实多阶段切换时，必须先明确请求、媒体缓存和上传中的 Stage 身份，不能仅改变页面标签而仍向旧 Stage 上传。

## 4. 视觉系统

### 4.1 基调

- 地图使用现有绘本插画，不在全屏画面外再套一层白色大卡片。
- 文字与按钮使用暖棕色、象牙白和低饱和强调色，避免多种彩色胶囊争夺注意力。
- 取消多层强发光、同时缩放的封面和持续旋转星星；保留少量帮助识别当前关的柔和动效。
- 标题使用现有 Fredoka；正文、操作和家长说明使用 Nunito，并提供清楚的中文系统字体回退。
- UI 图标统一为干净的 SVG；不使用文字字符拼凑菜单、窗口控制、前后箭头等图标。
- 初始 token 取自确认草案：主文字 `#62462f`，主要操作 `#ad643b`，暖白表面 `#fffcf6`；必须以可读性检查为准，不沿用草案偏浅的小字。
- 普通控件圆角约 10–14px，浮层约 18px；间距使用 4/8/12/16/24/32 的有限序列。

### 4.2 可读性

- 正文不以 10–12px 草案字号直接上线：对话建议 18px 左右，手机不小于 16px；辅助说明至少 14px。
- 不靠文字阴影解决复杂背景上的对比问题。关卡标题用局部实色底托住，顶层操作用轻量半透明底。
- 长章名和长课名允许换行，不用缩小到不可读来保持单行；目录保留完整名称。
- 触摸目标至少 44×44px；状态除颜色之外，还必须有图标、文字或其他明确形态区别。

## 5. 地图

### 5.1 顶部浮动操作

左上角为菜单按钮和当前 Stage 的简短标识；右上角显示当前 Stage 的完成数量和账号入口。两边独立布局，章标题放在下方，不挤在工具栏内。

顶部没有完整白色标题栏。登录、管理入口仍然可达，不因简化画面被移除。

### 5.2 章节与节点

保留十个章节沿连续路径排列的体验，不改成课程卡片网格，也不因弹出目录改为一次只加载一章。

- 当前课：清楚的主要入口，低频柔和强调；无 demo 时以关卡编号与状态图标呈现，不是巨大空白玻璃方块。
- 完成课：保留 demo 封面和单一完成标识；孩子可以进入详情回看自己的表演。无 demo 封面时使用完整设计的回退状态。
- 后续课：较弱的强调与锁定标识；有 demo 时保留可预览提示。
- 不把「在目录里选中」设计成「已经完成」或「当前待完成」，三者状态分离。

节点尺寸按有效宽度适配，不再把旧的桌面/手机节点像素和左右栏比例当成必须保留的产品规则。对应测试应更新布局断言，但继续保留状态机、稳定排序和唯一主题等行为测试。

路径按真实节点中心计算；字体加载、窗口大小改变、移动端横竖屏切换后重新测量。避免旧位置缓存导致路径与节点脱离。

### 5.3 插画适配

不同宽高比使用明确的构图焦点，不能简单把同一竖图放大后裁掉整幅内容。现有素材先复用；缺图保持可读、有设计的回退，不要求本轮补齐全部章节美术。

背景层与业务滚动容器共享可靠的视口基准，避免手机端 absolute/fixed 混用导致背景随长页面错位。保留章节切换时的轻量交叉淡入。

## 6. 左上角课程目录

### 6.1 内容与布局

目录按以下顺序展示：当前 Stage、三个 Stage 入口、能力主题、可折叠的家长选课说明、章节与课程列表、账号管理入口。

- 桌面：约 340px 宽的悬浮目录；地图仍可看见，但不接受背景交互。
- 手机：左侧抽屉，占宽度的大部分，保留少量遮罩区作为关闭提示；目录内容独立滚动，关闭入口始终可见。
- 打开时展开当前所在章节并使其可见；用户可以展开其他章节。
- 当前课程、课程的完成状态分别表达；计数来自真实 library，不硬编码示例值。
- 点击任意课关闭目录并打开真实课程详情。不是仅替换标题或滚动到空节点。
- 从详情返回地图时恢复进入详情前的地图位置；目录不会破坏原有 Prev/Next 课程顺序。

### 6.2 交互与无障碍

菜单按钮必须有名称、`aria-expanded` 和关联容器。展开后焦点移入目录，键盘焦点限制在浮层内；背景设为不可交互并锁定其滚动。

点击关闭、点击遮罩或按 Escape 均关闭；关闭后焦点回到来源按钮。双端不能出现穿透点击、两个浮层同时争夺焦点、关闭后仍无法滚动等问题。

未来 Stage 使用原生禁用按钮和可见 Planned 提示；不能让点击无反应的普通按钮伪装成可用入口。

## 7. 课程详情

延续 B 的暖色基调，但对话区使用安静的实色阅读底，不让绘本细节穿过正文。

阅读顺序为：返回/目录 → 课名与章节 → 示范和表演 → A/B/C 完整对话 → Replay Together → 家长说明与制作工具 → 上一课/下一课。

### 7.1 视频优先

- 桌面并排显示 Watch & Learn 与 Your Turn；保持同等媒体尺寸和清楚的操作层级。
- 手机以可访问的两个页签切换示范/自己的表演，一次主看一个视频；不是把两个大视频顺序堆在屏幕顶部。
- 切换页签时暂停被隐藏的视频，避免后台声音；从手机变为桌面时恢复双栏，不销毁现有录制状态。
- 示范空状态说明尚未添加；表演空状态以明确的录制按钮为主，不再只显示一个含义不明的加号。
- 家长仍能添加/替换 demo；录制失败仍可上传文件。不得把真实功能替换成设计占位按钮。
- 录制中阻止离开当前课或切走 Your Turn，提示先停止录制；停止后若有未保存录像，离开前提供“留在这里”和“放弃录像并离开”的确认，不自动保存或丢弃。
- 从一个详情切换到另一个详情时回到阅读顶部，停止旧媒体并防止旧异步请求覆盖新课。

### 7.2 对话、复练与家长工具

- 保留所有 A/B/C 台词和角色标签，不为视觉精简省略内容或更改台词。
- 角色名来自课程，不硬编码成爸爸与孩子；孩子台词用适度背景差异突出，不把成人输入弱化到难读。
- 两张 Replay Card 保留完整 setting / change / challenge，不重新压缩成一句替换提示。放在对话之后，手机可折叠但必须可发现。
- Can-Do、Trigger、Core/Stretch/Repair、Parent Support 放在 For the Grown-up 区域，默认收起，不挤占孩子观看前两屏。
- A/B/C prompt 及复制、demo 制作入口归入家长工具，默认收起；数据缺失使用诚实的空状态。
- Prev/Next 在手机可使用底部导航区，但必须为内容预留等高空间，包含底部安全区，不覆盖台词和按钮。

## 8. Electron 与 Web 分层

Electron 已使用 `frame: false`。本轮去掉的是独立可见标题栏和对业务标题的侵入式控件注入，不是删除退出或窗口管理能力。

- 顶部右侧保留最小化、最大化/还原和关闭，使用真实 preload 提供的能力。
- 地图顶部中央留拖动区域；所有按钮、目录、视频控制、正文和弹出内容必须 `no-drag`。
- 菜单/录制确认浮层打开时，不允许不可见拖动层挡住浮层。
- 不强制启动全屏；保留窗口调整、最大化和还原。
- Web 不显示假窗口按钮，不创建空白的 Electron 标题栏占位。
- 用一个明确的 shell 层管理窗口能力和样式，避免 MutationObserver 不断向不同业务标题插入控件。
- 登录页、管理页沿用同一 shell 原则，不能在独立页面上失去关闭或拖动窗口的能力。

## 9. 响应式与滚动

| 宽度 | 设计规则 |
| --- | --- |
| 小于 768px | 手机抽屉、视频页签、单列阅读、安全区底部导航 |
| 768–1023px | 紧凑桌面布局、浮动目录、视频双栏；低高度下正常滚动 |
| 1024px 及以上 | 完整桌面布局、双视频、舒适正文宽度；地图保留全幅空间 |

Electron 的 800×600 最小窗口属于紧凑桌面布局；不能只测试最大化窗口。

使用动态视口高度 `dvh` 并提供 `vh` 回退，处理 `safe-area-inset-*`。删除禁止缩放的 viewport 限制。桌面与手机分别验证高度变化、横屏、长标题和系统缩放。

地图与详情各自只有一个明确的主滚动容器；打开目录只让目录滚动。浏览器缩放、手机工具栏收放后，不出现页面底部不可达或顶部控制漂移。

## 10. 实现边界

- 课程读取、文件存储、认证与视频处理不作无关重构。
- 纯的阶段展示映射、菜单状态与媒体页签状态放入可测试模块；DOM 逻辑按 shell、目录和详情职责组织，不继续向巨大的主文件堆放所有行为。
- 页面文字与交互由 HTML/CSS/JS 实现，不将设计截图用作静态页面。
- 共享样式先定义 token，再改组件，避免在旧样式结尾追加多轮相互覆盖的断点补丁。
- 本轮不生成 Stage 2/3 内容，也不增加跨 Stage 自动升级。
- 隐藏不适用的工具不是删除工具；功能迁移必须有实际入口和测试覆盖。

## 11. 验收

### 11.1 功能

登录 → 地图 → 左上角目录 → 展开章节 → 打开课 → 查看 A/B/C → 展开 Replay/家长说明 → 下一课 → 返回地图。

同时验证账号切换/登出、管理员入口、prompt 复制、视频播放/暂停、录制或文件上传与错误状态。真实摄像头、麦克风或 Electron 无法验证时，必须明确列为未验证，不能用模拟测试代替真实平台验收。

### 11.2 窗口与尺寸

至少检查桌面 Web 1440×900、Electron 默认/最大化窗口与 800×600、手机 390×844、窄屏 360×740、横屏 844×390。手机 Chromium 与真实 iOS Safari 分开报告，不能因桌面模拟通过就宣称 Safari 已通过。

### 11.3 数据状态

覆盖无视频、仅 demo、已有 performance、混合锁定/完成、图片缺失、加载失败、超长标题、无 prompt、录制失败、上传失败和未保存录像。

使用隔离测试媒体与测试用户；不在孩子的真实录像目录写测试素材。

### 11.4 视觉与自动测试

- 核对布局、字号、留白、颜色、图标、插画裁切、空状态、动效与手机重排。
- 完成态不能被误认成目录选择态；未来 Stage 不能被误认成可用内容。
- 不允许横向溢出、文字被悬浮控件遮挡、焦点丢失、拖动层吞点击或隐藏视频继续播放。
- 执行 JS 语法检查、全部 JS 测试、全部 pytest 和课程完整校验。
- 本文编写前基线为 Python 87 项、JS 11 项通过；这是旧界面基线，不是新版 UI 的验收结果。
