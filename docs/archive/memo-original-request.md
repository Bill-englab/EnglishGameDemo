# 原始需求备忘（Original Request）

> 记录日期：2026-08-01
> 范围：冻结"我们要做什么、为什么"，作为英语 role-play 学习网站后续设计与实现的基线。

---

## 1. 背景

- **服务对象**：一个 4 岁孩子，已具备基础英语交流能力。
- **教学者**：父亲（英语流利），长期与孩子用英文交流、role-play，积累了大量对话素材。
- **痛点**：孩子能交流，但**句式偏基础、不够丰富**。
- **已有资产**：`roleplay-dialogues/` 下已按主题分好 10 个目录，是现成的课程骨架——

  `01-wants-requests` · `02-refusing-bargaining` · `03-asking-help` · `04-where-locating` · `05-why-how-come` · `06-feelings-preferences` · `07-reasoning` · `08-recounting-day` · `09-reporting-others` · `10-planning-predicting`

## 2. 目标（讨论收敛后）

这个网站**不是教学引擎，而是"进度 + 奖杯"层**：

- 真正的语言教学发生在**线下**——父亲与孩子 role-play、反复练。
- 网站的职责：把每一次完成的 role-play，**可视化为游戏般的进度与成就**，给孩子"我搞定了"的正反馈。
- 原始表述中的"句式更高级"**不再作为网站直接追踪的指标**；它是线下练习的目标，不是网站要量化显示的东西。

## 3. 产品形态

- 参考形式：**Two Dots** 式——一条向上的主线，由一关关节点组成。
- 每个关卡 = 一个 role-play 场景。
- 完成一关 = 点亮**一颗星**（只一颗，**无 1/2/3 星分级**——分级需要一个尚未定义的评判轴，且与"练到熟练才记录"的机制自相矛盾，故砍掉）。
- 关卡需解锁：上一关完成后，下一关才开放。

## 4. 核心机制（每关两段视频）

每个关卡包含**两段视频**，各司其职：

| 视频 | 来源 | 作用 |
| --- | --- | --- |
| `demo.mp4` | 备课阶段用 AI 生成的动画 | 给孩子"看样板"——演示这段对话怎么演 |
| `performance.mp4` | 父子照 demo 排练后，录下孩子的表演 | 给孩子"看自己"——这才是真正的奖励 |

教学逻辑：**样板 → 练 → 演出来 → 录下来**（标准 I-do / We-do / You-do）。

> **关键认知**：真正给孩子多巴胺的不是星星，是回头看自己的表演录像。星星只是入口，"我的表演回放"才是主舞台。

## 5. 技术架构

- **本地运行**的网站（不部署公网）。
- **文件系统即数据库**：每个关卡一个带序号的文件夹，网站扫文件夹即可知道一切，零上传基建。
- **上传方式**：父亲**手动**把 `performance.mp4` 放进对应关卡文件夹。保持简单——不做上传页、不写后端上传接口。

文件夹约定（示意，需与现有 `roleplay-dialogues/NN-topic/` 结构对齐——"关卡粒度"是单主题一关、还是一主题多场景，待定）：

```
NN-xxx/
  meta.json          ← 关卡标题、对话文案、场景描述
  demo.mp4           ← AI 演示，备课阶段就放进去
  performance.mp4    ← 孩子表演；此文件存在 = 星星点亮
```

状态规则（三句话讲完）：

- **关卡顺序** = 文件夹名前缀排序。
- **关卡解锁** = 上一关文件夹里存在 `performance.mp4`。
- **星星点亮** = 当前文件夹里存在 `performance.mp4`。

## 6. 两个阶段

1. **备课阶段**：父亲独立完成——搭网站、写每个场景的文案、用 AI 生成 `demo.mp4`。
2. **使用阶段**：父子一起闯关——看 demo、练、录表演、放进文件夹、星亮。

> **瀑布式风险**：不要"备完整套课再上"。先**贯通一关**（一个关卡 + 能录能放能点亮），本周就和孩子试一次，用真实反应验证，再扩展到其余主题。

## 7. 待自检的风险（父亲 owning）

| 风险 | 说明 | 守则 |
| --- | --- | --- |
| AI 演示视频质量 | 当前 AI 视频做"两角色对话"仍偏弱（短、抖、嘴型对不上、角色不一致），孩子可能模仿到 glitch 而非对话。 | 备课前先验证工具能否产出可用的对话动画，再决定批量生成。 |
| 录像变考核 | "练到熟练再录"可能把 role-play 从游戏变成考试；4 岁孩子一旦感到被测，会开始躲避。 | 录像应是游戏的自然高潮，不是另加的小考；留意孩子是否开始找借口躲。 |
| 备课节奏 vs 消费节奏 | 父亲造关速度若跟不上孩子闯关速度，地图会"断更"，孩子被锁住等爸爸，动力崩。 | 接受地图缓慢生长，或先备好足够缓冲。 |
| 手机→电脑的传文件摩擦 | Windows 无 AirDrop，手机视频进到本地文件夹这一步可能比想象麻烦。 | 已选"手动放文件"；首次贯通一关时实测这一步到底要几秒。 |

## 8. 下一步

- 贯通**第一关**的最小路径：本地站 + 一个关卡 + `demo.mp4` + 手动放 `performance.mp4` + 自动点亮。
- 用第一关和孩子真实跑一次，再决定是否扩展到完整 10 个主题。
